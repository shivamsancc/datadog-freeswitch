## 6. Draft pull request

**Title:** `Add FreeSWITCH integration`

**Description:**

> ### What does this PR do?
> Adds a community Agent check for [FreeSWITCH](https://signalwire.com/freeswitch). It connects to the Event Socket (ESL), authenticates with either the shared password or a restricted `userauth` directory user, and reports availability, uptime and channel count with two read-only commands (`uptime s`, `show channels count`). No events, no call control.
>
> Metrics: `freeswitch.can_connect`, `freeswitch.uptime`, `freeswitch.channels.active` (channels, not calls), `freeswitch.collection.duration`, `freeswitch.collection.errors` (tagged `error_type`: `connect`, `timeout`, `auth`, `protocol`, `parse`). No service check (availability is a gauge, as guidance prefers metrics).
>
> ### Motivation
> There is no maintained Datadog integration for FreeSWITCH. The earlier attempt (#1609) was closed for inactivity. I am willing to maintain this integration.
>
> ### Design and security notes
> - Stdlib only (plus `datadog-checks-base`); no subprocess or threads.
> - Strict client-side command allowlist; bounded frames (8 KiB headers, 64 KiB bodies), timeouts and run deadline; one reused connection, at most one reconnect per run.
> - Password is `secret: true`; never logged or placed in exceptions or tags.
> - With `username` set the check uses `userauth` and **refuses the account unless FreeSWITCH advertises `Allowed-API` as exactly `uptime,show`**; it never falls back to the shared password.
> - Known limitations: FreeSWITCH matches `esl-allowed-api` on the first word only, so `uptime,show` also allows other `show` subcommands; the shared-password mode cannot be restricted; ESL is plain TCP; host names are resolved by the OS and cannot be interrupted (IP addresses avoid this).
>
> ### Testing
> - 137 unit tests against a fake ESL server (timeouts, framing limits, auth failures, restarts, secrets, allowlist, multi-instance, fail-closed policy); 94 % coverage.
> - `ddev validate all freeswitch` (11/11), `ddev test -s` (ruff, mypy), wheel build.
> - Manual: FreeSWITCH 1.10.12; Datadog Agent 7.80.3 (Linux, aarch64, container) installed with `agent integration install`; `configcheck` shows the password masked; `agent check freeswitch` against a real FreeSWITCH (shared-password mode) and fixture servers for failures and `userauth` policy.
> - Not tested: a live restricted `userauth` user for the refusal cases (source analysis and simulated responses only); package-installed hosts; x86-64; FreeSWITCH other than 1.10.12.
>
> ### Open questions for reviewers
> `manifest.owner`, `display_on_public_website`, `source_type_id`, initial version / changelog form, whether a service check is wanted, direct socket use, and the `mypy-deps` entry in `hatch.toml`.
>
> ### Review checklist
> - [ ] PR has a meaningful title
> - [x] Feature has tests
> - [ ] Git history is clean
> - [x] Documentation is part of this PR (README)
